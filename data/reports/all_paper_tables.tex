\title{Resilient RAP Framework: An Adaptive Hybrid-Quantum Architecture for End-to-End Schema Reconciliation}
\maketitle

\begin{abstract}
Modern Reproducible Analytical Pipelines (RAP) suffer from severe processing bottlenecks when encountering structural schema drift in real-time, high-velocity data streams. Traditional reconciliation requires synchronous CPU branch checking or manual conditional interventions, inducing significant latency penalties. Rising costs in classical computing hardware and concerns about the environmental impact of inefficient LLM usage are also increasing. This paper presents an improved iteration of the Resilient RAP Framework, assessing the validity of an autonomous orchestration layer that introduces a 12-qubit Variational Quantum Classifier (VQC), deployed on both a 24-qubit QPU and a 156-qubit QPU, to evaluate and route schema drift characteristics on-the-fly. By implementing a dual-run pre-warmup phase on AMD Instinct accelerators, we completely isolate HIP kernel compilation cold starts. Our dual-stage gatekeeper dynamically routes anomalous packets between lightweight classical CPU heuristics and heavy GPU-based models (BERT/GPT). Compared to brute-force GPU reconciliation, the hybrid quantum routing network maintains a highly resilient 78.40\% average system accuracy on physical IBM quantum hardware. By intelligently offloading deterministic drifts to CPU paths, the architecture reduces active GPU resource utilization by about three quarters, ultimately achieving a significant reduction in compute requirements relative to classical LLM reconciliation pipelines.
\end{abstract}

\section{Introduction \& Motivation}
When schemas change, many things break in data engineering and data science. Dependencies and linkage references can lose their utility once schema naming conventions evolve. In Official Statistics, this can be remedied manually in time for future iterations of data releases. In high-stakes and high-elocity data streams, such as Formula 1 car and ICU monitoring systems, a mid-race sensor replacement or monitoring system change can break data lineage. Corrupted data packets due to physical damage to sensors (such as in a Formula 1 race), can also impact the quality of data once it is ingested into a monitoring system. 

In order to mitigate such changes in high-stakes and high-velocity telemetry streams, the Resilient RAP (Reproducible Analytical Pipeline) is proposed. It incorporates an intelligent schema reconciliation layer to a traditional telemetry ingestion pipeline. In the event that schema drift is identified, the layer automatically identifies its semantic meaning and maps it to the correct schema name for the data set. 

Multiple reconciliation methods are used, such as CPU-bound methods (Regex and Levenshtein), and GPU-bound (LLMs and decoders). In order to optimize resource usage, a routing system is proposed. This paper assesses the viability of multiple routing systems, such as Quantum-enhanced routing using a physical QPU (IBM's Heron r2 and the VLQ Quantum Computer in Ostrava, Czechia), GPU-accelerated (VQC simulation), and traditional CPU routing.

\section{Research Question}
Can adaptive hybrid classical-quantum routing improve schema reconciliation across heterogeneous computing platforms? This study evaluates a hybrid classical-quantum reconciliation process against classical and quantum reconciliation methods. In order to assess the methods, we logged the accuracy and latency for each reconciliation method on all packets for a homogeneous reconciliation and computing method, and compared the results to that of a routed, hybrid classical-quantum pipeline. A successful application of a hybrid classical-quantum reconciliation pipeline optimizes latency and accuracy while reducing compute needs, falling back to low compute CPU-bound reconciliation over GPU-accelerated reconciliation, when possible.

\subsection{Cross-Platform Benchmarking Protocol \& Methodological Consistency}
To ensure rigorous methodological comparability between the AMD Instinct MI250X (ROCm 6.0), NVIDIA GH200 Grace Hopper (CUDA 12.8), and NVIDIA Blackwell B300 (CUDA 13.0) evaluation environments, all software dependencies, precision modes, and batching constraints were held strictly invariant:
\begin{enumerate}
    \item \textbf{Software Stack \& Framework Native Execution}: Models were executed using native backend stacks—ROCm/HIP on AMD MI250X and native CUDA/cuDNN on NVIDIA GH200 and B300—over identical higher-level software versions (PyTorch, Hugging Face \texttt{transformers}, \texttt{sentence-transformers}, and Qiskit Aer GPU).
    \item \textbf{Batch Size}: All streaming telemetry benchmarks enforced a strict real-time single-packet batch size ($B=1$) to reflect live microservice SLA bounds.
    \item \textbf{Precision Settings}: Transformer encoders (\texttt{all-MiniLM-L6-v2} and \texttt{bge-base-en-v1.5}) were evaluated under FP16 mixed-precision, Gemma was loaded under 4-bit NF4 quantization, and VQC Aer simulator runs utilized double-precision (FP64) statevector evaluation across all architectures.
    \item \textbf{Power \& Thermal Profiling}: All platforms operated under standard vendor persistence modes at factory TDP limits (700W for GH200; 560W per MI250X board). Dual warmup iterations were executed prior to metric logging to completely isolate GPU kernel compilation cold starts.
\end{enumerate}

\section{Related Work}

Schema drift is a well documented phenomenon in multiple domains. Robin's paper on schema drift was used for the establishment of an existing issue in data pipelines~\cite{Robindrift}. This issue can be observed in the domains selected for testing, such as sporting, healthcare, science and general telemetry. In order to maintain a consistent level of corrupted packets, chaos was injected in the pipeline, as demonstrated by Basiri's 2016 paper on chaos engineering~\cite{Basiri_2016}. Since public-facing APIs are production-ready, they do not typically have corrupted data, so a simulation was required to assess the reconciliation strength.

In terms of quantum computing applications, Huang et al.'s paper on quantum machine learning demonstrated that it was a preferable method to classical machine learning in some engineered datasets, establishing a concept for this paper~\cite{Huang_2021}. The proposed quantum autoencoder for anomaly detection in Sakhnenko et al.'s paper was used as a basis for the quantum routing to optimize the use of different reconciliation methods~\cite{Sakhnenko_2022}, which reserves heavy compute for processes that require it, and reverting to more lightweight computing for all other tasks. Osei et al.'s paper on hybrid-quantum process evaluation suggests that these processes should be evaluated on an end-to-end basis, rather than stage by stage in isolation~\cite{OseiHPE}, so this pipeline will be evaluated as a whole. Similarly, Kanazawa et al. suggest that it is difficult to evaluate and track runtime metrics of quantum workflows. They propose an observability architecture specific for hybrid-quantum processes, which eliminate redundant workflow processes on expensive HPC and quantum computers~\cite{KanazawaObservability}. Havl{\'\i}{\v{c}}ek et al.'s supervised quantum enhanced learning feature spaces is used as a foundation for the $ZZ$ Feature Map implementation, leading to the assignment of the different drift types to their own qubit. ~\cite{Havlicek_2019}. The number of qubits used was selected in order reduce qubit overhead in the 24- and 156-qubit QPUs assessed in this manuscript. Kandala et al.'s paper on hardware efficient eigensolvers was used as a basis for output qubits, which allowed us to assign two qubits to represent each of the potential reconciliation models available for selection.~\cite{Kandala_2017}. Pérez-Salinas et al.'s paper on quantum classifiers is used as a basis for converting the qubits into a classical bit output~\cite{P_rez_Salinas_2020}, which provides a classical identifier for each type of reconciliation path. In Kandala et al.'s 2026 IBM paper on Quantum Advantages ~\cite{Kandala2026QuantumAdvantage}, the authors argue that the practical utility of quantum computing requires "trusted quantum computation", which involves verifying non-Clifford quantum workflows without relying solely on classical simulation. While our work applies to a different application domain, it similarly explores a hybrid quantum-classical workflow by combining VQC measurement outcomes with lightweight CPU-bound classical heuristics (Levenshtein and regex) before invoking GPU-accelerated embedding models when required. While this manuscript was in preparation, IBM's work emphasizing the importance of trusted quantum computation and hybrid quantum-classical workflows was published. Our empirical evaluation complements this perspective by investigating adaptive routing for resource-efficient schema reconciliation.

\section{Methodology}
\subsection{Variational Quantum Routing Architecture}
To eliminate severe compute and latency bottlenecks from using GPU-intensive models over CPU, such as Gemma \texttt{(gemma\_e2b)}, and to a lesser extent, BERT \texttt{(sentence-transformers/all-MiniLM-L6-v2)} and BGE \texttt{(BAAI/bge-base-en-v1.5)}, drifted telemetry packets are routed dynamically through a 12-qubit Variational Quantum Classifier (VQC)~\cite{Havlicek_2019}.
For each corrupted or anomalous packet identified by the classical fast-path check, the pre-processing layer extracts a 10-dimensional feature vector $\mathbf{x} \in \mathbb{R}^{10}$ describing its structural chaos/entropy, datatype shifts and string-edit properties (such as \texttt{field\_count}, \texttt{nesting\_depth}, \texttt{key\_edit\_distance\_mean}, and binary structural flags). Each feature is normalized to the interval $[0,1]$ and is subsequently scaled to $[0, \pi]$:
\begin{equation}
\mathbf{x}_{\text{scaled}} = \mathbf{x}_{\text{norm}} \times \pi
\end{equation}

These features are mapped to the quantum state space on qubits 0 through 9 using a non-linear $ZZ$ Feature Map across two repetitions~\cite{Havlicek_2019}. This entangling angle encoding captures non-linear, higher-order feature interactions prior to variational optimization.

\subsubsection{Parameterized Ansatz and Measurement}
The trainable layer of the VQC employs a 12-qubit \texttt{RealAmplitudes} ansatz spanning 10 feature qubits (listed in Table~\ref{tab:vqc_feature_mapping}) and 2 dedicated output qubits (listed in Table~\ref{tab:vqc_output_mapping})~\cite{Kandala_2017}. The ansatz consists of parameterized Single-Qubit $Y$-rotation gates ($R_y(\theta)$) interleaved with entangling CNOT gates, allowing the circuit to map correlations between high-dimensional metadata and the appropriate target reconciler.

\section{Data Ingestion and Chaos Engineering}
For multi-domain testing, data was sourced from 9 distinct APIs: OpenF1 (Formula 1 telemetry), Finnhub (stock market telemetry), SpaceX (aerospace telemetry), OpenWeather (weather telemetry), the United States Food and Drug Administration (healthcare/ICU telemetry), National Hockey League (hockey telemetry), OpenSky (aviation telemetry), The Union of European Football Associations (football telemetry), and TfL Transit Predictions (London transit telemetry). From each API, 2,500 packets were extracted and stored for consistency, for a total of 22,500 packets to be used for cross-domain validation and shadow runs/QPU training.

A shadow run was conducted for QPU comparison, and an additional 2,500 packets were run for JSON and schema alteration in the QPU.

\subsection{Reconciliation Architecture Specifications}

Table~\ref{tab:reconciler_specifications} summarizes the six reconciliation methods evaluated. The first two, Regex and Levenshtein, are CPU-bound and have the lowest computational cost. Each is specialized for a distinct type of matching: Levenshtein performs character-level edit distance calculations, while Regex performs rule-based pattern matching. The next model, \texttt{sentence-transformers/all-MiniLM-L6-v2}, is a Sentence Transformer based on the MiniLM encoder architecture that generates semantic sentence embeddings for contextual similarity matching. The following two models are embedding models: \texttt{bge-base-en-v1.5} is a locally hosted dense embedding encoder, while Cohere's \texttt{embed-english-v3.0} is a cloud-hosted embedding model accessed through a vector embedding API. Finally, Google's \texttt{gemma-4-E2B} is the smallest model in the Gemma 4 family evaluated in this work. It is a decoder-only, GPT-style autoregressive large language model that performs reconciliation by leveraging contextual natural language understanding and generation.

\section{Threats to Validity/Limitations}
Since Gemma4-E2B is a smaller autoregressive decoder model, it can be concluded that there is limited benefit to incorporate such models in environments where sub-millisecond latency is required for schema drift reconciliation. Quantum compute allocations are difficult to secure, limiting the amount of quantum training that can be conducted for a project. 

As previously mentioned, due to the low-availability of IBM Open Instance QPU time, it is possible that this cannot be used on a live telemetry stream. To mitigate constant use, LUMI and IBM's Quantum Platform use a SLURM batching process.

Additionally, some API sources are cyclically offline during distinct periods (such as Finnhub outside of trading hours, UEFA/NHL/F1 outside of competition periods, and SpaceX outside of launch events, for example). In order to conduct benchmarking on all API sources concurrently, historical data was sampled for some data sources.

The \texttt{all-MiniLM-L6-v2} model has a limitation of 256 characters before it truncates inputs, which could reduce its accuracy in the unlikely event there are extremely complex variable names~\cite{bert}.

\section{Conclusion}
The most efficient routing option was the VQC simulator on the MI250X, GH200, and B300 accelerators, while the CPU processes were significantly faster. Random Forest had a comparable accuracy to the VQC simulator with less than 1/1000th of the associated latency. The IBM QPU router exhibited considerably lower latency and accuracy than GPU and CPU reconciliation, which suggests that physical deployment of this type of pipeline is constrained by hardware noise and availability that are observed in a contemporary environment.
